# Ручная проверка

Как убедиться, что очередная итерация работает. Не заменяет просмотр
консоли браузера - он обязателен (см. CLAUDE.md).

## Запуск

```
./dev.sh          # сервер + фронт, Ctrl+C гасит оба
./dev.sh reset    # то же с чистой базой
./dev.sh check    # тайпчек + smoke_test, во втором терминале при живом сервере
```

Первый запуск сам создаст `server/.venv` и поставит `node_modules`.

## Два игрока на одной машине

Сессия хранится в cookie, а cookie у каждого адреса свои:

- ГМ - http://localhost:5173 (первый раз - по ссылке из `./dev.sh gm`)
- игрок - http://127.0.0.1:5173, входит по имени и паролю, которые завёл ГМ

Окна поставь рядом: всё, что делает один, должно сразу появляться у
другого. Сменить пользователя: кнопка выхода справа в шапке.

Красные 401/403/400 в консоли при неверном пароле, неверном ключе или
коротком пароле - это ответ сервера на ошибку ввода, норма. Без ошибки
ввода красного быть не должно.

Красного в консоли быть не должно. Предупреждения React DevTools и

## Автоматические регрессии BUGS.md

Используется pytest/TestClient и node:test. Для браузера добавлен только Playwright (dev-зависимость с package-lock); дополнительные тестовые фреймворки не нужны. Идентификаторы B01-B12 соответствуют записям в BUGS.md. Сценарии Chromium не используют force-клики, пропуски или CSS-подмены.

### Запуск

Из корня репозитория:

```bash
(cd server && .venv/bin/python -m pytest tests -q)
(cd web && npm ci)
(cd web && npm test)
(cd web && npm run typecheck)
(cd web && npm run build)
(cd web && CHROMIUM_PATH=/usr/bin/chromium npm run test:browser)
```

Если системного Chromium нет, установить браузер командой `cd web && npx playwright install chromium`, затем запускать `npm run test:browser` без CHROMIUM_PATH. Загрузка браузера требует разрешённого сетевого доступа. Использованный в облаке системный Chromium доступен по `/usr/bin/chromium`.

Браузерный набор поднимает uvicorn и Vite на свободных локальных портах, создаёт временную SQLite/каталог загрузок/ключ ГМ и отдельные аккаунты. Обычная база и аккаунты пользователя не затрагиваются. Перед сценариями он выполняет **существующий server/smoke_test.py** на этом живом сервере; его код возврата обязателен, пропущенный/провалившийся smoke не считается успехом. После прогона процессы останавливаются и временная база удаляется. Снимки страниц при отказах сохраняются в `/tmp/laterna-browser-results` (путь можно задать BROWSER_RESULTS_DIR).

Чтобы проверять именно отрисованное состояние Pixi, тестовый маршрут главного модуля сохраняет ссылки на созданные SceneStage. Конструктор, обработчики, рендерер, транспорт и сервер не подменяются. Проверяются реальные mouse/touch/drag-and-drop, DOM-геометрия, загруженная текстура, кадры настоящих WebSocket-соединений и последствия переподключения. Наблюдатель учитывает асинхронное монтирование/размонтирование StrictMode. Сохранённая сцена и активная сцена восстанавливаются между тестами, включая завершившиеся ошибкой.
