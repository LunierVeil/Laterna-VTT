# Как внести вклад в Laterna VTT

## Issue и Pull Request

1. Проверьте, есть ли похожее обсуждение. Для ошибки опишите версию Laterna,
   окружение, шаги, ожидаемый и фактический результат. Для предложения опишите
   задачу и кого она затрагивает. Существенные изменения архитектуры и форматов
   данных сначала обсудите в Issue. Не прикладывайте ключи, пароли, ссылки
   мастера, реальные сохранения и приватные материалы. [Issues](https://github.com/LunierVeil/Laterna-VTT/issues)
2. Создайте ветку от актуального `master` в форке или в основном репозитории,
   если у вас есть права. Делайте коммиты по одной связанной задаче, пишите
   сообщения коммитов на русском. Сверьтесь с границами слоёв, правилами
   серверной авторизации и совместимости сохранений. Команды и высокочастотные
   данные рендера обрабатывайте по существующим контрактам.
   [AGENTS.md](AGENTS.md) · [Архитектура](docs/ARCHITECTURE.md)
3. Запустите проверки по типу изменения. Для документации выполните
   `python3 scripts/check-doc-links.py` и `git diff --check`. Для backend
   выполните `server/.venv/bin/python -m pytest server/tests -q`, для
   служебных скриптов — `server/.venv/bin/python -m unittest discover -s scripts/tests -v`.
   Для frontend выполните `npm --prefix web run typecheck`,
   `npm --prefix web test` и `npm --prefix web run build`. При изменении
   игрового сценария проверьте его в Chromium по инструкции. Используйте
   изолированные тестовые БД, каталоги загрузок и ключи.
   [Проверки и окружение](docs/DEVELOPMENT.md#все-проверки)
4. Откройте Draft PR в `master`. Укажите связанный Issue, что меняется,
   как это проверили и откуда взялись код и материалы. Укажите соавторов.
   Отвечайте на замечания в том же PR. Перед готовностью к merge проект
   требует независимое review конкретного HEAD и актуальный Full CI
   с `CI required`. [Git workflow](AGENTS.md#git-workflow) · [CI/CD](docs/CI_CD.md)

## Происхождение кода и материалов

В описании PR укажите, какие части написали вы. Для заимствованных частей
(включая фрагменты кода, изображения, шрифты и тестовые данные) дайте ссылку
на источник и точную версию или коммит, лицензию и требуемую атрибуцию.
Обозначьте изменённые и неизменённые части. Если происхождение неизвестно
или условия неясны, обсудите материал до включения. Получите разрешение
работодателя, заказчика или соавтора, если права принадлежат им. Подробности
о полномочиях передавайте по согласованному закрытому каналу.

## Авторские права и CLA

Ваши авторские права на собственный вклад сохраняются. Основная Laterna VTT
остаётся бесплатной и открытой под GNU AGPL-3.0-or-later. Проект CLA описывает
дополнительное разрешение владельцу использовать, изменять, распространять и
перелицензировать охваченный вклад, включая коммерческое и закрытое использование.
Оно позволит работать над платными сервисами и дополнениями там, где права
на весь задействованный материал это допускают.
[Проект CLA](CLA.md) · [Политика открытого проекта](docs/legal/OPEN_SOURCE_POLICY.md)

Сейчас CLA находится на рассмотрении. Подписание не требуется.
Если владелец утвердит соглашение и процесс принятия, в PR будет ссылка
на полную действующую редакцию и сведения об обработке данных.
Прочитайте их до подтверждения. Каждый правообладатель или его
уполномоченный представитель подтверждает права на свою часть. Открытие PR
и сообщения об ошибках не заменяют явное согласие.
[Проект процесса принятия](docs/legal/CLA_AUTOMATION.md)
