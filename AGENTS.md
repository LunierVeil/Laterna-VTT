# Работа с Laterna VTT

Self-hosted VTT: FastAPI, React/TypeScript, PixiJS 8 и Zustand для UI.
Перед изменениями прочитайте релевантные документы: [архитектура](docs/ARCHITECTURE.md),
[roadmap](docs/ROADMAP.md), [разработка и проверки](docs/DEVELOPMENT.md).

- Сервер авторитетен для игрового состояния, команд и проверок прав. Броски выполняются на сервере.
- Секретные объекты, изображения и данные ГМ не передавать неавторизованным игрокам.
- Сохранять API/команды и совместимость данных; учитывать WebSocket, reconnect, seq и cmd_id.
- Рендер сцены остаётся в PixiJS; не обновлять Zustand на каждый кадр drag-preview.
- Не изменять пользовательские базы и сохранения без явного разрешения.
- Новые функции сопровождать тестами. Для затронутых компонентов запускать backend pytest,
  frontend tests, TypeScript, production build и browser tests; не ослаблять проверки ради CI.
- Commit, push, merge, force-push, релизы и разрушительные операции требуют разрешения пользователя.

Планы, а не реализованная архитектура: Design System → упрощённый FSD → централизованный
Zustand с логическими slices/actions/selectors → модульный монолит FastAPI.
Не начинать эти этапы в задаче подготовки snapshot. Инвариант — серверная проверка команд
и прав, без требования навсегда размещать всю игровую логику в одном файле.
