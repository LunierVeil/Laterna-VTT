---
name: spec-first
description: Превращает задачу или GitHub Issue Laterna VTT в краткую техническую спецификацию с проверяемой приёмкой. Применяется при изменении поведения или контрактов.
---

1. Возьми результат и границы из задания или указанного Issue. Код, тесты и решения владельца сверяй на текущем HEAD. Определи затронутые backend/frontend точки входа и зависимости, отметь противоречия между запросом и действующими контрактами.
2. Опиши наблюдаемое поведение в нормальном, ошибочном и граничном сценариях. Зафиксируй функциональные и существенные нефункциональные требования, совместимость API, событий и сохранений, согласованные решения, OPEN-вопросы и исключения из scope.
3. Для REST/WS/media проверь, кто определяет права, какие данные и кому отправляются, что происходит при отказе и reconnect. Для хранилища сверяй [backend-контракты](../../../server/AGENTS.md) и [решения Beta](../../../docs/BETA_DECISIONS.md): DataHome/SQLite, backup/restore, Alembic, совместимость схем и отказ до записи при нарушении условий. Для клиентских границ см. [web/AGENTS.md](../../../web/AGENTS.md).
4. Оформи результат по [шаблону](../../../docs/agent-workflow/TASK_TEMPLATE.md). Для каждого критерия укажи наблюдаемый исход и конкретную команду, существующий тест либо сценарий с ожидаемой проверкой. Отметь будущий тест как запланированный. Для небольшой правки достаточно нескольких пунктов в чате.
5. Если от OPEN-решения или отдельного разрешения зависит реализация, укажи вопрос и остановись до зависимых изменений. Спецификация сама по себе не разрешает работу с пользовательскими данными.
