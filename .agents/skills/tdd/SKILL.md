---
name: tdd
description: Проводит и фиксирует Red → Green → Refactor для изменения поведения Laterna VTT, используя существующие pytest, frontend unit, Playwright и служебные тесты.
---

Возьми наблюдаемый критерий из задачи или спецификации. Выбери ближайший тестовый слой по [командам разработки](../../../docs/DEVELOPMENT.md#все-проверки). Для документации или объективно неприменимого TDD кратко зафиксируй причину.

1. **Red.** До реализации добавь воспроизводимый тест. Выбери регрессию, отказ или границу. Для сбоя записи или транспорта внедряй контролируемый отказ только в тестовом fixture. Для повторных команд и хранилища проверь идемпотентность или управляемый отказ, если они входят в контракт. Запусти профильный тест и зафиксируй ожидаемое падение поведенческого assertion. Ошибка окружения, сбора или импорта требует диагностики и повторного Red. Если код уже изменён, фактический Red можно проверить в изолированной копии предшествующего состояния. Без прогона отмечай Red как неподтверждённый.
2. **Green.** Сделай минимальную реализацию, повтори тот же тест и запусти соседние проверки по критериям. Сохрани assertions и уровень проверки. Unit-тест не заменяет проверку взаимодействия, когда от него зависит критерий.
3. **Refactor.** При необходимости улучши структуру без изменения поведения. Повтори профильные и затронутые регрессионные тесты. Если отдельный рефакторинг не понадобился, отрази это в результате.

Для одного случая укажи pytest node ID в `server/tests`, запусти `node --test tests/<имя>.test.ts` из `web/`, выбери `npm run test:browser -- --suite <suite>` по [манифесту](../../../web/tests/browser/run.mjs) или `python -m unittest discover -s scripts/tests -p 'test_ci_gate.py'` для служебных проверок. Используй только временные fixtures, включая DB/uploads/ключи. При предложении взять реальные данные или чужие артефакты без разрешения останови зависимую проверку и замени их синтетическими.

Для каждой фазы запиши команду, проверенное состояние (SHA и локальный diff при наличии), результат и для Red причину падения. Сохрани падающий тест при диагностике, без удаления и ослабления assertions.
