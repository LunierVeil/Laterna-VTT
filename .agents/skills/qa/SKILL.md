---
name: qa
description: Выполняет риск-ориентированную проверку уже реализованного изменения Laterna VTT и выдаёт QA-отчёт по критериям приёмки и фактическим результатам.
---

1. Прочитай критерии приёмки и diff на проверяемом SHA или в рабочем дереве. Проследи изменённые точки входа и зависимости. Если критерий или проверяемый diff отсутствует, явно отметь ограничение покрытия и утверждай только проверенное.
2. Собери матрицу «критерий и риск | сценарий | ожидаемый результат | тест | факт». Для каждого изменённого контракта выбери нормальный, отрицательный, граничный и актуальный регрессионный сценарии. Следуй [маршрутам проверок](references/coverage.md) по области изменений.
3. Выполни профильные проверки из [DEVELOPMENT](../../../docs/DEVELOPMENT.md#все-проверки) в изолированной среде. Для пользовательского сценария наблюдай результат через browser assertions. Плановые и пропущенные проверки отчитай отдельно с причиной. Полный обязательный набор применяется на этапе, указанном в [Git workflow](../../../AGENTS.md#git-workflow).
4. Отчитай SHA или рабочее дерево, команды, результаты и покрытие. Для каждого дефекта дай **Blocker** (безопасность, сохранность или невозможность обязательной приёмки), **Major** (существенная регрессия) или **Minor** (ограниченное влияние), ссылку на файл либо проверку, условия, ожидаемый и фактический результат. При отсутствии дефектов укажи проверенные сценарии и пробелы. QA-отчёт даёт доказательства для ревью. Независимое решение принимается по Git workflow.
