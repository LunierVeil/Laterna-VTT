# PB-05 A — контракт путей DataHome

[Issue #46](https://github.com/LunierVeil/Laterna-VTT/issues/46) задаёт
приёмку PB-05. Продуктовые решения — [LTR-DEC-004 и G1](BETA_DECISIONS.md).

| Хранилище | AS-IS | Цель |
| --- | --- | --- |
| SQLite | `lanterna.db` относительно cwd, обычно `server/` | Один файл `lanterna.db` в DataHome |
| Uploads и ключ ГМ | `server/uploads` и `server/gm_key.txt` | `uploads/` и `gm_key.txt` в том же DataHome |
| Windows ZIP | Launcher запускает сервер из каталога распаковки | Установка заменяема, данные по умолчанию в `%LOCALAPPDATA%\LaternaVTT` |
| Portable | Выделенного выбора нет | Явное включение, каталог привязан к установке |
| Dev и fixtures | `DATABASE_URL`, `UPLOAD_DIR`, `GM_KEY_FILE` | Изолированные overrides и существующий Linux dev workflow |

## Resolver этапа A

`resolve_storage(env, server_dir=..., cwd=...)` возвращает mode, корень и пути.
Входные каталоги абсолютные. `server_dir` определяется местоположением приложения.
Для выбора путей не нужны доступ к каталогу и создание файлов. Конфигурация
SQLite хранится в объекте SQLAlchemy URL, чтобы символы в имени файла
не интерпретировались как параметры URL.

- `LANTERNA_DATA_HOME` задаёт абсолютный корень вручную.
- `LANTERNA_PORTABLE=1` выбирает `data/` рядом с `server/`. Отсутствие
  переменной или `0` оставляет обычный выбор. Явный корень и portable
  взаимоисключающие. Имена переменных и размещение `data/` — техническое
  предложение реализации для review.
- Обычный Windows-режим требует абсолютный `LOCALAPPDATA`. Если он отсутствует
  или неверен, resolver сообщает об ошибке. Смена cwd и каталога ZIP не меняет
  корень хранилища.
- В явном DataHome и portable пути определяются только из корня. Отдельные
  overrides с этими режимами несовместимы. На Windows изолированный запуск
  может передать все три overrides вместе с абсолютными файловыми путями.
  Частичный набор отклоняется, чтобы случайно не смешать хранилища.
- Для существующего Linux dev workflow сохраняются SQLite относительно cwd,
  uploads и ключ в `server/`, а также частичные overrides. Относительные
  файловые overrides разрешаются относительно cwd. Dev Compose сохраняет
  возможность задать PostgreSQL через `DATABASE_URL`.

На этапе A launcher, конфигурация FastAPI и пути запуска сохраняли
прежний контракт. Подключение backend и проверка состояния описаны в B.
Проверка совместимости, legacy detection и fail-closed preflight нужны
до активации нового пути, поскольку смена пути иначе может скрыть старый стол.

## OPEN и следующие этапы

- Продуктовый default Linux остаётся OPEN. Предложение для рассмотрения —
  `$XDG_DATA_HOME/laterna-vtt` с fallback на `~/.local/share/laterna-vtt`,
  при условии preflight и проверки прежних путей.
- UX, способ сохранения portable-выбора и поведение при смене режима
  уточняются до интеграции launcher в D.
- Перенос Alpha требует отдельной утверждённой процедуры и проверяемого
  backup/restore. B обнаруживает прежние данные и останавливает запуск при
  неоднозначном или несовместимом состоянии. До B `init_db()`
  вызывает `create_all` и additive `ALTER TABLE`, поэтому найденную старую
  БД нельзя передавать туда до проверки.
- Межпроцессное владение каноническим DataHome относится к C. Windows ZIP,
  сохранность при замене пакета и итоговая приёмка относятся к D.

## Этап B — startup preflight

Конфигурация backend использует resolver этапа A при импорте. Импорт приложения
не создаёт uploads, SQLite и файл ключа. В lifespan сначала проверяются пути
и состояние всего набора. Затем разрешён один из следующих сценариев.

| Состояние | Действие |
| --- | --- |
| Настоящий первый запуск | Все три артефакта отсутствуют, доступен родитель каталога и не найдено прежнее хранилище. Процесс резервирует SQLite эксклюзивным созданием, готовит uploads, инициализирует схему и демо-сцену, затем загружает или создаёт ключ. |
| Совместимая SQLite | Нужны существующие uploads и непустой файл ключа либо заданный ключ из env. Preflight проверяет целостность, ожидаемые таблицы и колонки, наличие кампании с активной сценой и доступ к файлам. Startup пропускает `init_db()` и создание демо-сцены. |
| Ошибочное или неполное состояние | Запуск останавливается до любых записей. Это относится к отсутствующей БД при наличии других артефактов, повреждённой или несовместимой SQLite, неожиданному типу пути, перенаправлениям и отказам доступа. |
| Внешняя PostgreSQL или явная in-memory SQLite | Существующая конфигурация dev/fixtures и её отдельная инициализация сохраняются. |

SQLite проверяется через read-only immutable connection, чтобы даже диагностика
не создавала журнал. Наличие `-journal`, `-wal` или `-shm` останавливает запуск
до чтения базы. Не удаляйте эти файлы вручную. Остановите прежний экземпляр
и сохраните исходный комплект перед проверенной процедурой восстановления.
После preflight SQLAlchemy открывает файловую SQLite с `mode=rw`, поэтому
исчезновение файла после проверки не приводит к его созданию драйвером.
`create_all` используется для новой SQLite, `ALTER TABLE` для существующей
SQLite на startup не выполняется. Процесс, прерванный во время первого запуска,
может оставить неполный комплект, который следующий запуск отклонит.

Перед созданием новой файловой SQLite проверяются известные предыдущие места:
каталог `server/`, cwd, `data/` рядом с `server/` и, на Windows, прежний выбор из
`LOCALAPPDATA`, если доступен. Проверка видит известные имена SQLite, её журналов,
uploads и ключа. Явная полная комбинация трёх per-file overrides считается
изолированным запуском. Из другого каталога распаковки обнаруживаются только
места, известные новому процессу. B не сканирует весь диск и не переносит
данные из чужой установки. При необходимости сохраните исходный каталог
и дождитесь утверждённой процедуры переноса.

Проверка путей отклоняет символические ссылки и Windows reparse points
в выбранной цепочке каталогов. Она не предоставляет межпроцессного
владения. Изменения файлов другим процессом между проверкой и запуском
остаются за границей B, блокировка DataHome относится к C. Если Windows ACL
препятствует записи, которую невозможно проверить без изменения файлов,
запуск сообщит об отказе при попытке подготовки. Windows ZIP и пункты меню
«Ссылка мастера» и «Копия базы» требуют отдельной приёмки в D.
