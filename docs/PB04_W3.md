# PB-04 — W3: контракт препятствий и серверный срез

Owner утвердил W3 в задании PB-04 (актуализировано 13.11.2026, Москва).
[Issue #45](https://github.com/LunierVeil/Laterna-VTT/issues/45) остаётся реестром
приёмки всего PB-04. Это решение не утверждает другие OPEN-пункты Beta.

## Семантика

| Вид | Обзор | Движение |
| --- | --- | --- |
| wall | `blocks_sight` | `blocks_movement` |
| window | `blocks_sight` | `blocks_movement` |
| door open | разрешён | разрешено |
| door closed/locked | запрещён | запрещено |

При `wall.add` обычное стекло (`kind=window`) получает `blocks_sight=false`,
`blocks_movement=true`. Явные boolean-поля задают независимые свойства: допускается
непрозрачное окно и окно без препятствия движению. У стены сохранён default true/true.
У обычной двери состояние приоритетнее обоих сохранённых флагов, включая legacy
комбинации с false. Неизвестное состояние двери не открывает проход/обзор.

Используются уже существующие колонки Wall. SQL schema, default колонок,
старые записи и сохранения автоматически не переписываются. Сохранённое окно
с `blocks_sight=true` остаётся непрозрачным, даже если создаваемое командой стекло
по умолчанию прозрачно. Миграций, DDL и конвертации JSON нет.

## Команды и ответственность

- `wall.add` и новая `wall.update` — только ГМ. Флаги обзора/движения принимают
  именно boolean, без coercion строк, чисел или null.
- `wall.update`: id, необязательные kind, door_state, blocks_sight,
  blocks_movement, x1/y1/x2/y2. Неуказанные свойства сохраняются, в том числе при
  смене kind. Координаты проверяются существующим finite/clamp-контрактом;
  нулевая длина отвергается. Ошибка откатывает изменения и seq.
- Событие `wall.updated` сохраняет ID/owner, seq и cmd_id. Старые команды
  door/remove и их права сохраняются. Общую стену с owner_id=null по прежнему
  может удалить игрок; это не разрешает ему wall.update или удаление стены ГМ.
- Движение проверяет geometry.path_blocked. Точный LOS использует scene_sight и
  PreparedGeometry. На границах сохраняются PB-01 epsilon и точные предикаты.
- Координаты прозрачных препятствий также валидируются до фильтрации оптики.
  Неизвестные kinds (secret_door/invisible и будущие типы), неоднозначный флаг,
  неверные координаты не превращаются в CLEAR. Права и manual FoW применяются
  независимо от геометрического результата.

## Projection и безопасность

Серверный capture включает полную геометрию. Штамп включает все сохранённые поля
стен; изменение окна отзывает устаревшую проекцию даже без изменения seq.
REST, initial/reconnect WS, events и media используют существующие PB-02 проверки
сессии/роли/сцены и freshness. В публичную проекцию допускается поддерживаемое
окно, но полностью скрытая manual FoW геометрия не выдаётся. Переходы при движении
стены под туман/из тумана используют remove/add; скрытые обновления — noop без ID.

Собственный токен и GM layer сохраняют прежние исключения. Прозрачность окна
не открывает NPC sheets или приватные вложения; она может разрешить только
портрет видимого NPC по действующему media ACL. Отзыв видимости закрывает новые
GET/HEAD/Range. Уже полученные байты невозможно отозвать.

Экспериментальная серверная visibility по прежнему включается флагом
`LANTERNA_EXPERIMENTAL_VISIBILITY=1`. Legacy flag-off media не объявляются
защищёнными этим срезом. Карта-подложка может передаваться целиком по LTR-DEC-003.

## Границы PR A и оставшаяся приёмка

Срез содержит серверный контракт, команды и backend regressions. Редактор окон,
их Pixi-визуализация и визуальная W3-геометрия — следующий PR B. До него PB-03
клиент при окне в snapshot консервативно закрывает визуальную маску как при
неподдерживаемой геометрии; разрешения сервера от этой маски не зависят. Новый UI
окон в этом срезе не выставлен. Это промежуточная интеграция, не готовый PB-04.

Нужны gameplay/Chromium приёмка нового UI, сравнение performance после реализации,
полный CI каждого test merge и нового master, обновление Issue/Project. Porthole
отложен до подготовки Beta 0.5. Следующий PB автоматически не начинается.

## Baseline до изменений

База: `81341f4f172b131ceb43ca224b5668081f423505`. Существующий PB-03 probe
`tests/browser/visual-lighting.mjs` выполнен до изменений кода, без параллельного
pytest/build/browser workload. Профиль PB-00: 30 tokens, 200 walls; 15 источников
заданы явно, без mapping emits_light. Сырые измерения:
[performance/pb04-before.json](performance/pb04-before.json).

Окружение baseline: Linux 6.18.57, AMD EPYC 9V74, cgroup quota 4 CPU,
лимит памяти 32 GiB; Python 3.12.14, Node 24.19.0, системный headless Chromium
154.0.8037.57, Vite development, viewport 1280×900. Это общая cloud-среда,
не эталон аппаратной GPU клиента. DPR и renderer исходный probe не записал;
они не подтверждены этим baseline. Для строгого сравнения рендера потребуется
расширить методику и при необходимости повторить базу на указанном SHA.

8 warm samples; nearest-rank quantile (`ceil(n*q)-1`), поэтому median для чётного
n — нижняя центральная выборка. Worker CPU median/p95: **40.0/73.2 ms**;
Canvas paint/update: **30.3/37.0 ms**. Один cloud-прогон не доказывает устойчивость
или отсутствие регрессии; среда общая. Heap-показатели включают JS/Pixi caches,
не измеряют worker heap/GPU memory и не доказывают отсутствие утечек. Эти числа
не FPS, не GPU frame time и не SLA. Сравнение после полного W3/UI ещё не выполнено.

Повторить с отдельным results directory на той же среде:

```bash
cd web
LANTERNA_EXPERIMENTAL_VISIBILITY=1 CHROMIUM_PATH=/usr/bin/chromium \
  BROWSER_RESULTS_DIR=/tmp/laterna-pb04-before node --test tests/browser/visual-lighting.mjs
```
