# Проверка пилота Workflow-04

Первичные проверки выполнены на рабочем дереве от `981266299efc20eea0256a8855e8f67c56652a77`.
Независимая runtime-приёмка [PR #88](https://github.com/LunierVeil/Laterna-VTT/pull/88)
относится к реализации на HEAD `cf5ac4be3e09c04ecba8691eaea8283013bb8576`.
Codex CLI **0.171.0**, Git **2.56.1**, локальный Python **3.14.10**.
Скрипт использует стандартную библиотеку Python 3.12. Fast CI проверяет
существующий набор служебных тестов на Python 3.12.

## Контракт и параметры

Пилот регистрирует один command handler для `Stop` в
[.codex/hooks.json](../../.codex/hooks.json). Событие относится к завершению
хода. Для дочернего завершения Codex документирует `SubagentStop`. Код
игнорирует это событие и повторный `Stop` с `stop_hook_active=true`.
`matcher` для Stop в этой версии не используется. Для `PreToolUse` и
`PostToolUse` matcher применяется к имени инструмента. Эти два события и
`SubagentStop` доступны в схеме CLI. Пилот их не регистрирует. PostToolUse
наступает после операции и не откатывает её.

Codex передаёт JSON через stdin. Handler читает поля события и cwd.
Выход 0 без вывода означает тихий результат. Для уведомлений выдаётся только
`systemMessage`. Поля `decision` и `continue` отсутствуют, код 2 не используется.
Общий бюджет Git составляет 1,5 с, лимит одного вызова — до 0,6 с,
лимит команды со стороны Codex — 3 с. Технический сбой или тайм-аут hook
не гарантирует остановку операции Codex.

Codex объединяет подходящие hooks из системного, пользовательского и доверенных
проектных слоёв от корня до cwd. Поэтому могут сработать несколько совпавших
записей. Здесь определение хранится только в `hooks.json`. Активность
`features.hooks` и trust конкретного определения проверяются отдельно.
[Официальная документация](https://learn.chatgpt.com/docs/hooks)

## Проверки в установленном CLI

Временная копия и отдельный `CODEX_HOME` без пользовательских данных.
Запуск `codex app-server --listen stdio:// --disable apps --disable plugins --disable remote_plugin`.
После `initialize` и `initialized` вызван `hooks/list` с `cwds` для корня,
`server/` и `web/`. Для доверенного проекта добавлен временный аргумент
`-c 'projects={"/path/to/fixture"={trust_level="trusted"}}'`
с фактическим путём тестовой копии. Hook trust отдельно не предоставлялся.

| Режим | Наблюдение в CLI |
| --- | --- |
| Проект не доверен | Проектный Stop отсутствует во всех трёх cwd. |
| Проект доверен | Ровно один Stop в каждом cwd. `matcher=null`, `enabled=true`, `trustStatus=untrusted`. |
| `--disable hooks` | Stop отсутствует во всех трёх cwd. |
| Тайм-аут изменён с 3 до 4 с во временной копии | CLI вернул другой `currentHash`, статус оставался `untrusted`. |

`skills/list` обнаружил все восемь навыков. `config/read` подтвердил лимит двух
агентов. Этот первичный прогон проверял обнаружение. Доверенный lifecycle
и один сценарий с `backend_review` проверены отдельно при runtime-приёмке.

## Launcher и Python

```bash
git diff --check
python3 -m json.tool .codex/hooks.json
python3 scripts/check-doc-links.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -p test_codex_hooks.py -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -v
```

Профильные проверки запускают точную команду из `hooks.json` через `sh -c` с
синтетическим Stop JSON либо вызывают скрипт напрямую для отрицательных случаев.
Проверены тихий чистый diff, WARN для обоих способов сравнения Git, отдельное
напоминание по Markdown, cwd в server/web, пропуск чужого дерева, symlink,
повреждённый JSON, неизвестные события, пропуск подозрительных Git-фильтров,
недоступный Git, сбой и короткий subprocess timeout. Снимки байтов файлов,
включая индекс Git, совпали. Диагностика не включает строки diff, stderr Git
или полный путь временной копии. Тесты прошли в среде без доступа к сетевым
сокетам. Launcher отказывается исполнять подменённый или недоступный скрипт.

Измерения прогона launcher через `time.perf_counter()`, 12 вызовов на режим.
Включён запуск Python и локального Git, без времени модельного хода.

| Сценарий в синтетической копии | Медиана | Максимум |
| --- | ---: | ---: |
| Чистый diff | 34,4 мс | 41,9 мс |
| Staged и unstaged whitespace | 39,6 мс | 54,6 мс |
| Те же изменения и Markdown | 40,4 мс | 50,8 мс |

Пилот проверяет обычные отслеживаемые файлы в ограниченных путях Laterna
с каноническим origin. Новые untracked файлы, symlink, данные, большие списки,
partial clone и настроенные внешние Git-фильтры вне автоматической проверки.
Проверку ссылок оставили в ручном preflight, поскольку текущий валидатор
обходит Markdown по всему дереву и при проверке якорей может читать цели вне него.
Нет оснований считать предупреждение о ручной проверке результатом валидатора.

## Независимая runtime-приёмка

Аудитор использовал Codex CLI 0.171.0 и изолированные рабочие копии.
В копии Laterna HEAD, `.codex/hooks.json` и Python-обработчик сверены
с проверенной реализацией PR #88. Синтетические изменения использовались
для staged, unstaged и Markdown-сценариев.

| Сценарий | Наблюдение |
| --- | --- |
| Ручной Trust и чистый ход | Аудитор подтвердил Trust текущего проектного Stop через `/hooks` и штатное завершение чистого хода без предупреждения. |
| Изменения | Stop автоматически диагностировал whitespace в staged и unstaged diff. Изменённый Markdown вызвал напоминание о ручной проверке ссылок. |
| Отключение | Аудитор подтвердил отсутствие запуска при `--disable hooks`. |
| `backend_review` | В журнале одного app-server зафиксирована одна пара `hook/started` и `hook/completed` при завершении родителя. При завершении дочернего хода запусков не зарегистрировано. Журнал для этого сценария содержит имена уведомлений без payload. Отнесение пары к Stop основано на единственной регистрации в проекте и времени завершения родительского хода. |
| Побочные эффекты | Аудитор подтвердил совпадение SHA-256 проверенных файлов и Git-индекса. |

### Failure и timeout

В двух временных Git-репозиториях со своими Stop-определениями аудитор вручную
подтвердил Trust и передал по одному модельному ходу в `codex app-server`
через `turn/start`. Перед началом `hooks/list` подтвердил один активный
проектный Stop со статусом `trusted` и тайм-аутом 3 с. Сессии использовали
`read-only` и `approvalPolicy=never`.

| Временный hook | Фактическое событие `hook/completed` | Результат хода |
| --- | --- | --- |
| Failure | `failed`, `hook exited with code 1`, 2 мс | Один Stop, один завершённый ход, один ожидаемый ответ. |
| Timeout | `failed`, `hook timed out after 3s`, 3001 мс | Один Stop, один завершённый ход, один ожидаемый ответ. |

Локальные записи RPC и сводки сверены. В каждом прогоне ID запуска совпал
у `hook/started` и `hook/completed`. За последующие 10 с повторного запуска
или дополнительного хода не зафиксировано. Манифесты до и после совпали
по всем 36 записям в каждом fixture. В манифест входили 24 хэша файлов,
включая `.git/index`, и 12 записей каталогов.

### Границы доказательств

Failure и timeout проверяют реакцию Codex на сбой **временных обработчиков**.
Тайм-аут дочернего Git-процесса в обработчике Laterna проверен отдельно
служебным тестом. Результат с `backend_review` относится к одному прогону.
Матрица покрывает Codex CLI 0.171.0 в проверенном окружении. Сочетания с
другими hooks, версиями CLI и платформами вне этой приёмки.

Временные fixture и сырые журналы хранятся локально вне репозитория.
Runtime-приёмка подтверждает поведение реализации на проверенном HEAD.
Финальное независимое review документации и Full CI актуального test merge
проходят по [Git workflow](../../AGENTS.md#git-workflow).
