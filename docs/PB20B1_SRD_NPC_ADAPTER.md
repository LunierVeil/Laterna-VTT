# PB-20B1 — адаптер SRD в черновик NPC

Адаптер преобразует валидированный снимок SRD 5.1 в JSON-совместимый черновик
редактора NPC для D&D 5e 2014. Источник снимка — `SrdCatalog.make_homebrew_draft`.
Вызывающая сторона загружает каталог, выбирает шаблон и выделяет идентификаторы.
[Каталог PB-20A](PB20A_SRD_BESTIARY.md) ·
[Спецификация PB-21A](https://github.com/LunierVeil/Laterna-VTT/blob/199364bb44b8f4c86c968451cecc450c984666ba/docs/PB21A_NPC_CONTRACT.md) ·
[Архитектурное решение](https://github.com/LunierVeil/Laterna-VTT/pull/99#pullrequestreview-6076256445)

## Интерфейс

```python
result = adapt_srd_npc(
    snapshot,                   # валидированный HomebrewDraft с origin
    catalog.manifest,           # SourceManifest того же каталога
    sheet_id=sheet_id,           # назначает вызывающая сторона
    card_ids={"traits": trait_ids, "actions": action_ids},
    legacy_mob_data=legacy,     # необязательный исходный JSON листа
)
```

`card_ids` содержит ровно заполненные исходные секции. В каждой секции
последовательность ID соответствует порядку исходных карточек. ID уникальны
в пределах листа. Повтор импорта с теми же входами даёт тот же результат.
После создания листа перестановка или изменение карточки сохраняет уже
присвоенный ID. `sheet_id`, ID снимка и ID шаблона имеют разные назначения.
Ошибка входных данных вызывает `ValueError`. [Адаптер](../server/app/bestiary/npc_adapter.py)

Результат содержит `draft` формы `NpcDraft` и отдельное
`import_metadata.catalog_schema_version`. SHA-256 в provenance относится к
PDF. Версия в import metadata относится к формату каталога. Место её
долговечного хранения определит интеграция PB-20B/21B.

## Сохранность данных

- `name` идёт в черновик, структурированные данные — в `statblock`. Сохраняются
  исходный текст движения, чувств, языков и защит, строковый CR, XP, AC с
  уточнениями, максимум HP и hit dice, все характеристики, спасброски и навыки.
- `AbilityScores` уже имеет lowercase-ключи. Названия спасбросков переходят
  из шести литералов SRD в lowercase `ability`. Optional `None` остаётся
  отсутствующим. `0` XP, AC и модификатора сохраняется.
- Секции обходятся в порядке исходного контракта. Пустые секции опускаются,
  `label/text`, пролог и заметка переносятся полностью. Spellcasting и
  Multiattack получают подсказку роли в той же карточке. Печатный recharge
  сохраняется в `usage`, включая диапазоны, тире и условие отдыха.
- `origin` обязателен. ID источника и SHA-256 сверяются с manifest.
  Диапазон страниц и последняя строка берутся из origin. Лицензия, атрибуция
  и реквизиты источника берутся из того же manifest.
- Переданный legacy JSON копируется рекурсивно, включая `null`, неизвестные
  ключи и вложения. Циклы, не-JSON значения и числа, которые нельзя точно
  представить в JavaScript, отклоняются.

Это граница импорта из строгого SRD. Ручные и изменённые NPC живут по контракту
редактора, который позволяет частичные и нестандартные данные. Адаптер работает
с максимумом HP листа. Текущие HP принадлежат токену. Подключение листа и
единственное каноническое хранилище NPC относятся к последующим этапам.

## Проверки

```bash
server/.venv/bin/python -m pytest server/tests/test_srd_npc_adapter.py -q
PYTHON="$PWD/server/.venv/bin/python" node --test web/tests/srd-npc-adapter.contract.mjs
```

Python сверяет каждый из 58 шаблонов: значения, необязательные поля, provenance,
порядок, ID и точное содержимое карточек. Все 12 существ с печатным recharge
проверяются независимо от их других способностей. Отрицательные сценарии
проверяют переданные ID, отсутствующий origin, расхождения manifest и legacy
JSON. Отдельно проверяются детерминизм, независимость снимков и отсутствие I/O.

Межъязыковой тест генерирует реальные 58 результатов Python, компилирует их
как литералы `satisfies NpcDraft` с точной опциональностью и проверяет
отрицательный контроль. Тот же TypeScript-контракт принимает ручной NPC с
нестандартным CR и характеристикой. В CI тест запускается с контрактом из
checkout. До интеграции PB-21A локально можно указать
`LATERNA_NPC_CONTRACT` с абсолютным путём к TS-файлу утверждённого SHA.
