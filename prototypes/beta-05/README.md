# Laterna VTT · Beta 0.5 UI Prototype

Интерактивный прототип для проверки сценариев мастера и игрока на Full HD при масштабе браузера 100%. Демонстрационная партия «Тени Грейвика» начинается в затопленном аббатстве. Игровые изменения живут в памяти вкладки. Настройки интерфейса и разведка описаны в разделе локального согласования.

## Запуск

**Для просмотра без dev-сервера.** После сборки откройте `dist/index.html` в Chromium или Chrome. В одном файле находятся интерфейс, карта, шрифты и демонстрационные данные.

**Для разработки.** Из `prototypes/beta-05` в распакованном архиве или в рабочем дереве репозитория:

```sh
npm ci
npm run dev
```

Откройте адрес, который выведет Vite. Для самостоятельной HTML-сборки выполните `npm run build` и откройте `dist/index.html`. Разработка и сборка проверены с Node.js 24.

## Стек

React 18, TypeScript, Vite, CSS и SVG. Общие токены, IconButton, диалоги, плавающие окна и меню находятся в `src/shared/`. Макеты работают на демонстрационных данных внутри вкладки.

## Сценарий для показа

Откройте «Тени Грейвика» → выберите сцену → **Редактировать карту** → поставьте стену двумя кликами и свет одним → **Ассеты** → выберите «Дубовый сундук» → разместите на карте. В правой панели **Персонажи → NPC / монстры → Добавить NPC / монстра** создайте NPC и разместите его. В **Материалы → Журнал** создайте письмо, закрепите его на ширме и нажмите **Показать игрокам**. В **Player View** откройте **Раздатки** и **Мой лист**. Вернитесь в **GM View**, начните бой, откройте и закройте ширму. Карта, материалы и бой сохранятся в этой вкладке.

## Границы кода

- `app/` связывает интерфейс и состояние. Данные кампаний находятся в `app/mock/`, имитация команд и состояние в `app/model/`.
- `pages/` композитно собирает экран кампаний и игровой стол. `widgets/` содержит карту, активность, ширму и композицию диалогов.
- `features/` содержит пользовательские операции и формы. `entities/` определяет общие модели и правила их отображения.
- `shared/` содержит UI, SVG-подложки и снимок канонического `web/src/shared/styles/tokens.css`. Прототип компонуется через props и callbacks.
- Текущий аудит сверён с master `7a35500e85175c0e3d4f57715f3e71ad134bedaf`, документации и PB-00…PB-26. На этом срезе уже видны визуальный worker и слой PB-03. Состояние прототипа и SVG-карта существуют отдельно от production Zustand, PixiJS, REST и WebSocket.

## Что согласовать перед переносом

1. Граница между игрой и редактированием, режимы выбора и привязки объектов, состав undo и поведение при параллельных правках.
2. Модель текущего обзора игрока (OPEN), серверное хранение индивидуальной разведки и сохранность при сбросе (MUST PB-15), визуализация закрытых дверей и препятствий.
3. Где игроку открывать полученную раздатку, как долго живёт временный показ, кто может редактировать материалы и как отзывать доступ. По умолчанию игрок управляет Эларой. При ручном создании или импорте активным становится новый герой.
4. Какие действия и карточки закреплять на ширме и нужно ли запоминать её раскладку. В демо ширму можно перемещать и растягивать поверх карты.
5. Форматы и ограничения UVTT, происхождение и каталогизация ассетов, состав проверенного бестиария, границы редактора NPC и системных слотов D&D 5e.
6. UX смены активной кампании при подключённых игроках, матрица LAN/Porthole, этапы preflight и подтверждения восстановления. Сценарии копирования и подключения в демо имитируются.

## Что работает локально и что остаётся макетом

Сцены мастера и партии, права взаимодействия, броски, редактирование листов и рассылка раздаток имитируются в памяти браузера. Импорт UVTT и LSS JSON читают выбранные локальные файлы. Сценарии подключения и восстановления демонстрируют интерфейс. Долговременное хранение, авторитетные проверки прав, сетевые сессии, окончательные правила обзора и полный SRD остаются задачами отдельных итераций.

Визуальная приёмка включает читаемость ширмы, плотность быстрых действий, скорость Dice Overlay, подсветку в гиде и раскладки листов. Остальные вопросы и границы переноса перечислены в аудите.

## Локальное согласование

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5175 --strictPort
```

[Игровой стол](http://127.0.0.1:5175/) · [Design Review](http://127.0.0.1:5175/?review=1). Review открывает нужную демонстрационную роль, сцену и окно. Прямые ссылки и границы утверждения перечислены в [APPROVED_UI.md](APPROVED_UI.md). `npm run build` даёт автономный `dist/index.html`. Для него сценарии открываются теми же query-параметрами.

| Где живут данные | Что относится к этой области |
| --- | --- |
| Память вкладки | Кампании и сцены, токены, декали и их детерминированные параметры, герои и NPC, инвентарь, материалы, чат, результаты и очередность боя, закрепления быстрых действий, положение плавающих окон. После полной перезагрузки открываются исходные демонстрационные данные. |
| Хранилище браузера | Раскладка листа по кампании и characterId, выбор сплошного фона ширмы, отключение анимации кубиков, факт показа приглашения в гид, клетки разведки по кампании, сцене и герою. Review сброса хранит собственные демонстрационные клетки. |

Review Mode нужен для согласования на локальном прототипе. Для группового просмотра после отдельного согласия владельца можно собрать `dist/index.html` и опубликовать его как отдельный статический артефакт через GitHub Pages. Сначала проверить видимость репозитория и возможность изолированного источника Pages, права на демонстрационные материалы и прямые query-ссылки на опубликованный HTML. HMR предоставляется локальным Vite.
