# Laterna VTT

Открытый self-hosted VTT, который мастер поднимает у себя.

Состояние: функционально завершённая альфа, использованная в реальных игровых сессиях. Подготовка инфраструктуры перед бетой; архитектурная перестройка не начата. Открытые полевые проверки перечислены в docs/BUGS.md. Работает сцена с сеткой и картой-подложкой,
токены, стены, чат и броски кубов. Динамического освещения пока нет - оно идёт после
того, как по карте станет можно просто играть.

## Что уже есть

- Сцена на PixiJS: панорама, зум, квадратная сетка
- Сцены: ГМ готовит их скрытыми и показывает игрокам, когда нужно
- Карта-подложка: загрузка PNG/JPEG/WebP, размер клетки под нарисованную сетку
- Токены: создание, перетаскивание с привязкой к клетке, имя, цвет, размер, удаление своих
- Стены: рисование цепочкой, удаление своих, блокировка движения **на сервере**
- Чат и броски кубов, общие на кампанию: `2d6+3`, `d20`, `4d6kh3`, `2d20kl1`, `1к8+4`, панель кубов
- Лист персонажа D&D 5e: форма, как в Roll20 - игрок заполняет сам, правила не проверяются
- Server-authoritative протокол: клиент шлёт команду, сервер рассылает событие

## Что осознанно не сделано

Динамическое освещение, динамический туман войны, автоматика правил в листе.
См. docs/ARCHITECTURE.md, раздел "Что осознанно отложено".

**Ручной туман - заглушка.** Мастер закрывает и открывает прямоугольники
инструментом «Туман». Под ним игрокам не уходят токены и стены. Но:
- туман не открывается от токенов - только руками мастера;
- нет памяти разведанного;
- картинка карты передаётся игроку целиком и скрыта только визуально:
  кто откроет DevTools, увидит карту под туманом (токены и стены - нет).
Динамический туман и свет - в бете.

**Без HTTPS.** Не выставляйте стол в интернет без HTTPS-прокси перед ним.

**Пинг:** Alt+клик по карте (на сенсорном устройстве - отдельная кнопка «Пинг») - кольцо с
именем у всех на 4 секунды.

## Вход

Открытой регистрации нет: аккаунт появляется только по ссылке от мастера.

1. Мастер открывает ссылку ГМ (её печатает `./laterna.sh gm`) или на экране
   входа жмёт «Я мастер - войти по ключу», и при первом входе придумывает
   себе имя и пароль.
2. Мастер во вкладке «Игроки» создаёт общую ссылку кампании и отправляет
   её всей партии. Она используется повторно до отзыва; приём новых игроков можно приостановить.
3. Новый игрок по ссылке придумывает имя и пароль; существующий входит в тот же аккаунт. Мастер пароли не знает.
4. Дальше все входят по имени и паролю, сервер сверяет их с хешем в
   базе. Сессия живёт в cookie 30 дней.

Забыл пароль - мастер жмёт «Сброс пароля» у игрока и отправляет новую
ссылку; по ней игрок задаёт новый пароль, старые входы перестают работать.
Игроку на другом компьютере в ссылке нужен адрес мастера в сети, а не
localhost - его печатает `./laterna.sh` при запуске.

Ссылка ГМ - запасной вход мастера, если он забыл пароль. Не показывай её
игрокам. Ключ хранится в `server/gm_key.txt`; сервер печатает ссылку
только в момент создания ключа, дальше - лишь путь к файлу. Удали файл -
при следующем старте будет новый ключ, и старая ссылка перестанет
работать. В docker задай `LANTERNA_GM_KEY`.

## Запуск

Первая игра через Porthole - [docs/FIRST_SESSION.md](docs/FIRST_SESSION.md).


### Играть: одной командой

```
./laterna.sh          # стол на http://localhost:8000 - и страница, и API
./laterna.sh porthole # игра через Porthole (Steam): только 127.0.0.1 и инструкция
./laterna.sh tunnel   # то же + ссылка для игроков из интернета
TUNNEL_VIA=ssh ./laterna.sh tunnel   # если провайдер режет туннели Cloudflare
./laterna.sh gm       # ссылка ГМ
PORT=9000 ./laterna.sh
```

Проверяемое окружение: Python 3.12 и Node.js 24 LTS (Node нужен для сборки и тестов). Первый запуск
сам ставит зависимости и собирает фронт, следующие - пересобирают его,
только если код менялся. Печатает адрес для игроков в локальной сети.
Порт в интернет не пробрасывать: по http пароли идут открытым текстом.

Игроки из интернета - `./laterna.sh tunnel`. Нужен `cloudflared`
(Arch: `sudo pacman -S cloudflared`, остальное - на сайте Cloudflare),
аккаунт Cloudflare не нужен. Скрипт печатает адрес вида
`https://…trycloudflare.com` - HTTPS даёт Cloudflare, роутер настраивать не
надо. Приглашения во вкладке «Игроки» сразу идут с этим адресом. Адрес
новый при каждом запуске. Ограничения попыток входа есть, но не заменяют HTTPS и стойкие пароли.

Если туннель не подключается («TLS handshake with edge error», порт
7844) - провайдер режет туннели Cloudflare. Тогда
`TUNNEL_VIA=ssh ./laterna.sh tunnel` - туннель через ssh (localhost.run),
ставить ничего не нужно. Весь вывод туннеля - в `server/tunnel.log`.

**В России** оба туннеля упираются в блокировки: страница начинает
грузиться («Загружаю стол…») и замирает - провайдеры обрывают соединения
с зарубежными хостингами после первых килобайт. Мастеру нужен рабочий
выход туннеля (у Cloudflare рвётся рукопожатие), а игрокам - VPN или
обход блокировок. Без этого - общая виртуальная сеть (Radmin VPN,
ZeroTier): игроки заходят по адресу мастера в ней, как в локальной сети.

### Docker (локальная разработка)

Текущий Compose содержит тестовые credentials и bind mounts исходников. Это dev-конфигурация, не production deployment.

```
docker compose up --build
```

Фронт: http://localhost:5173, API: http://localhost:8000

После `git pull` с новыми зависимостями фронта (например, шрифты
`@fontsource`) `./dev.sh` и `./laterna.sh` сами запускают `npm ci`. Вручную:
`cd web && npm ci`.

### Разработка

```
./dev.sh          # сервер :8000 + vite :5173 с горячей перезагрузкой, Ctrl+C гасит оба
./dev.sh reset    # с чистой базой
./dev.sh check    # тайпчек + smoke_test при живом сервере
```

`dev.sh reset` удаляет базу и uploads: использовать только с одноразовыми тестовыми данными по явному разрешению, не для проверки пользовательской кампании.

Ручные проверки после изменений - в docs/CHECKLIST.md.

### без docker, вручную

Бэкенд (SQLite, никакой настройки):

```
cd server
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000 --no-proxy-headers
```

Фронт:

```
cd web
npm install
npm run dev
```

### Проверка

```
cd server && .venv/bin/python -m pytest tests                # без сервера
cd server && python smoke_test.py                             # при живом сервере
```

`./dev.sh check` выполняет только часть проверок. Полный набор backend/frontend/build/Chromium и изолированный smoke описаны в [DEVELOPMENT.md](docs/DEVELOPMENT.md).

Проверяет порядок seq, подтверждение команд по cmd_id, блокировку
движения стеной и серверный бросок кубов.

## Управление

| | |
|---|---|
| Колонка слева | инструменты; название и подсказка - при наведении |
| Инструмент "Выбор" | ЛКМ тянет токен, по пустому месту - панорама; Shift+клик или Shift+рамка выделяет группу, Esc снимает выбор |
| Инструмент "Токен" | клик ставит токен в клетку |
| Инструмент "Стены и двери" (ГМ) | клик-клик рисует отрезок, дальше цепочкой; ПКМ - панорама |
| Инструмент "Стереть" (ГМ) | клик по стене удаляет её |
| Delete / Backspace | удалить выбранные свои и общие токены; ГМ - любые |
| Колесо, «−» / «+» внизу справа | зум |
| Вкладка «Сцены» (ГМ) | создать, открыть, показать игрокам, удалить; карта и размер клетки |
| Вкладка «Игроки» (ГМ) | приглашения, сброс пароля, удаление |
| `/r 2d6+3` в чате | бросок |
| Панель кубов под чатом | ЛКМ добавляет куб, ПКМ убирает, ± модификатор, преимущество и помеха в один клик; у ГМ «Скрытно ГМ» |

## Структура

```
server/app/
  main.py        websocket, REST, применение команд под локом сцены
  handlers.py    единственное место, где меняется состояние
  models.py      SQLAlchemy, стены со всеми флагами с первого дня
  dice.py        парсер и бросок, только на сервере
  geometry.py    пересечение отрезков для валидации движения
  hub.py         комнаты, рассылка, лок на сцену
web/src/
  net/socket.ts  seq-дедупликация, оптимистичные изменения, переподключение
  scene/stage.ts вся PixiJS-сцена, React внутрь не лезет
  state/store.ts только состояние интерфейса
```

Перед тем как трогать код, прочитайте docs/ARCHITECTURE.md - там решения,
а не описание.

## Исправления по BUGS (01.11.2026)

В списке персонажей доступна кнопка «На карту»; строку листа можно перетащить на карту. Токен персонажа принадлежит владельцу листа, даже когда его поставил мастер. При перетаскивании Alt отключает привязку. Инструмент «Пинг» работает тапом. На узком экране кнопки внизу сворачивают панели и инструменты.

Урон сначала расходует временные хиты. Токен без своей картинки использует актуальный портрет листа. Удаление листа обновляет привязки у открытых клиентов. При потере связи клиент получает новый снимок; сердцебиение обнаруживает зависшее подключение.


## Стабилизация альфы: игра в группе

Во вкладке «Игроки» есть одна общая ссылка для партии, копирование, пауза новых регистраций и отзыв. Уже вошедшие игроки сохраняют доступ после отзыва; сброс пароля остаётся отдельной одноразовой ссылкой. Для LAN/Porthole проверь поле «Адрес сервера для игроков», для туннеля используется PUBLIC_URL. Не отправляй игрокам мастер-ключ.

В сценах янтарным выделена карта игроков, отдельно подписана открытая у ГМ. Превью открывает карту одним кликом/тапом; меню позволяет переименовать её без перехода и открыть настройки. NPC/мобы получили «Снаряжение» с теми же карточками и редактором описаний, что у персонажа.

При перетаскивании обычный токен остаётся на подтверждённом месте, а ghost и линия показывают намерение разрешённым участникам. Отпускание отправляет прежнее проверяемое сервером движение; Esc отменяет preview. Стены продолжают проверяться сервером, скрытые токены и секретные изображения игрокам не передаются. Это не поиск пути и не автоматический обход стен.
