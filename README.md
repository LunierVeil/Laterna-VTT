# Lanterna

Открытый self-hosted VTT. Рабочее название, переименовать не проблема.

Состояние: ранний прототип. Работает сцена с сеткой и картой-подложкой,
токены, стены, чат и броски кубов. Динамического освещения пока нет - оно идёт после
того, как по карте станет можно просто играть.

## Что уже есть

- Сцена на PixiJS: панорама, зум, квадратная сетка
- Сцены: ГМ готовит их скрытыми и показывает игрокам, когда нужно
- Карта-подложка: загрузка PNG/JPEG/WebP, размер клетки под нарисованную сетку
- Токены: создание, перетаскивание с привязкой к клетке, имя, цвет, размер, удаление своих
- Стены: рисование цепочкой, удаление своих, блокировка движения **на сервере**
- Чат и броски кубов, общие на кампанию: `2d6+3`, `d20`, `4d6kh3`, `2d20kl1`, панель кубов
- Server-authoritative протокол: клиент шлёт команду, сервер рассылает событие

## Что осознанно не сделано

Динамическое освещение, туман войны, листы персонажей, аутентификация.
См. ARCHITECTURE.md, раздел "Что осознанно отложено".

**Аутентификации нет.** Имя приходит query-параметром и никак не
проверяется. Не выставляйте это в интернет.

## ГМ

При старте сервер печатает в терминал ссылку вида
`http://localhost:5173/?gm=...`. Кто открыл её - мастер: ему доступны
сцены, карта и размер клетки. Ссылку не показывай игрокам. Ключ хранится в
`server/gm_key.txt`; удали файл - при следующем старте будет новый, и
старая ссылка перестанет работать. В docker задай `LANTERNA_GM_KEY`.

## Запуск

### docker

```
docker compose up --build
```

Фронт: http://localhost:5173, API: http://localhost:8000

### без docker, одной командой

```
./dev.sh          # сервер + фронт, Ctrl+C гасит оба
./dev.sh reset    # с чистой базой
./dev.sh check    # тайпчек + smoke_test при живом сервере
```

Ручные проверки после изменений - в CHECKLIST.md.

### без docker, вручную

Бэкенд (SQLite, никакой настройки):

```
cd server
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Фронт:

```
cd web
npm install
npm run dev
```

### Проверка

```
cd server && python smoke_test.py
```

Проверяет порядок seq, подтверждение команд по cmd_id, блокировку
движения стеной и серверный бросок кубов.

## Управление

| | |
|---|---|
| Инструмент "Выбор" | ЛКМ тянет токен, по пустому месту - панорама |
| Инструмент "Токен" | клик ставит токен в клетку |
| Инструмент "Стена" | клик-клик рисует отрезок, дальше цепочкой; ПКМ - панорама |
| Инструмент "Стереть" | клик по своей стене удаляет её; чужие подсвечены блёкло и не удаляются |
| Delete / Backspace | удалить выбранный свой токен |
| Колесо | зум к курсору |
| «Сцены» в шапке (ГМ) | создать, открыть, показать игрокам, удалить |
| «Карта» в шапке (ГМ) | загрузить, заменить или убрать карту; размер клетки |
| `/r 2d6+3` в чате | бросок |
| Панель кубов под чатом | ЛКМ добавляет куб, ПКМ убирает, ± модификатор, преимущество и помеха в один клик |

## Структура

```
server/app/
  main.py        websocket, REST, применение команд под локом сцены
  handlers.py    единственное место, где меняется состояние
  models.py      SQLAlchemy, стены со всеми флагами с первого дня
  dice.py        парсер и бросок, только на сервере
  geometry.py    пересечение отрезков для валидации движения
  hub.py         комнаты, рассылка, лок на сцену
web/src/
  net/socket.ts  seq-дедупликация, оптимистичные изменения, переподключение
  scene/stage.ts вся PixiJS-сцена, React внутрь не лезет
  state/store.ts только состояние интерфейса
```

Перед тем как трогать код, прочитайте ARCHITECTURE.md - там решения,
а не описание.
